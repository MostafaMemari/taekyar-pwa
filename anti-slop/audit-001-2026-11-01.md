# Audit 001 — taekyar-pwa

- Mode: **after** (session override)
- Date: 2026-11-01
- Scope: 248 source files (`src/**`), tokens in `src/app/globals.css`, no dependency or config changes
- Method: static reading + rule greps. **No browser click-through** (R-35 unverified, see §4).
- Rulebook: `.agents/skills/antislop/antislop.md` (antislop v3.2.x core rules R-01…R-40)

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

## 1. Findings

### 1.1 HIGH — Hard Gate

**1. R-25 — secondary text fails WCAG AA in the light theme**
`--ink-6: #9ca3af` is used as *text* in 106 places at 12px (`text-ink-subtle`, and `text-ink-faint` 20 more). On `#ffffff` that is **2.6:1**, on the canvas `#f7f8fa` **2.5:1**; AA needs 4.5:1 for text under 18px. Dark theme is fine (`#7f8aa0` on `#11151d` ≈ 4.9:1).
Fix (one token): set light `--ink-6` to ~`#667085` (4.6:1) and keep `#9ca3af` for non-text only, or stop using `ink-6` for labels. `ink-7`/`faint` must stay decorative (1.5:1).

**2. R-02 — em dash in UI copy (28 occurrences)**
`student-form-options.ts` (20 belt descriptions), `src/app/page.tsx:60`, `verify-otp-form.tsx:103`, `coach-signup-form.tsx:145`, `student-signup-step-documents.tsx:114`, `student-attendance-panel.tsx:31`, `student-attendance-report.tsx:108`, `student-insurance-panel.tsx:62`, `coach-profile-form.tsx:148`, `security-screen.tsx:51`, `settings-screen.tsx:179`, `settings-screen.tsx:186`, `dashboard-overview.tsx:70` (placeholder).
Fix: `،` `|` `()`; the `"—"` placeholder becomes a skeleton or "ثبت نشده".

**3. R-37 — no declared design direction**
There is no `DESIGN.md` (or equivalent) and the three dials (ENERGY / RHYTHM / MOTION) are never stated. By this rule the current UI is a **draft without direction**: the identities exist in code (crimson accent token, Vazirmatn, dark coach band, belt motif) but are not written down, so nothing constrains the next screen from drifting.
Fix: one `DESIGN.md` with identity, palette, type, radius, shadow, and dials (`ENERGY 2 / RHYTHM 1 / MOTION 1` matches what is built).

**4. R-39 — async state is visual only**
148 `Skeleton` uses, but `aria-busy` only on 2 elements and no `aria-live` region for loaded/empty transitions. A screen-reader user gets no signal that data arrived.
Fix: `aria-busy` on the container that swaps skeleton → content (2-3 shared spots), one `role="status"` for the "خالی" transitions.

### 1.2 MEDIUM — Purpose-Gate

**5. R-13 / R-01 — glow dose on the welcome screen**
`logo-mark` glow (20px, 68% brand), `role-card-hero` glow (44px, 75%), `shadow-brand-xl` on brand buttons, plus the crimson radial inside `coach-band`. Four glow sources on one screen exceeds the 1-2 dose cap.
Fix: keep the accent glow on the primary role card only; flatten `logo-mark`.

**6. R-19 / R-39 — decorative loop without reduced-motion**
`src/app/page.tsx:17` uses `animate-ping` (infinite pulse) for a status dot with no `motion-safe:` guard, so it runs for users who asked for reduced motion.
Fix: `motion-safe:animate-ping`.

**7. R-04 — icon identity is the library default**
All 30+ icons are Lucide thin-stroke (bell, users, calendar, clipboard…). Each is content-relevant, so this passes relevance, but nothing in the icon layer belongs to taekwondo. Only `taekyar-mark.tsx` (belt strip, glyph, wordmark) is original.
Fix (optional): 3-4 custom glyphs (belt knot, mat corner, hwarang stance) for the tab bar or section heads.

**8. R-40 — hero image has no reserved ratio**
`src/app/page.tsx:31` uses `<Image fill>` inside a `min-h-[120px] max-h-[340px] flex-1` figure: no `width`/`height`, no `aspect-ratio`, so the hero box can shift while the photo loads.
Fix: give the figure an `aspect-[4/3]` (or fixed height) so space is reserved.

### 1.3 LOW — Quality Locks

**9. R-31 — no written one-line reasons.** Colors, spacing, radius, shadows are all deliberate now, but none of it is recorded (same root as finding 3).

**10. R-11 — three radius families, undocumented.** Card `2xl` (1.125rem), control `lg`, CTA/badge/chip full pill. The hierarchy is real (size-driven) but has to be stated in `DESIGN.md` or it will drift back to "everything pill".

**11. R-29 — palette breadth.** One brand hue plus four semantic status colors (success, warning, danger, info). Within budget only if the four are treated as semantics, not decoration; currently badges are the main color carrier, so keep an eye on it.

**12. R-05 — uniform section rhythm.** Every coach screen is `band → sheet → SectionHeading + Card`. For a task app (RHYTHM 1) this is a defensible choice, but it is currently an accident of habit, not a declared decision.

## 2. What passes

- **R-03** tap targets: header, bell, quick actions and list actions are 44px; cards act as full-width targets.
- **R-17 / R-18 / R-36** no fabricated numbers, testimonials or claims; every figure comes from the API or is a skeleton.
- **R-24** every tab-bar and in-page link points to a route that exists; no "coming soon" ghosts.
- **R-26** no dead controls found; 21 icon buttons, all with `aria-label`.
- **R-32** one global `:focus-visible` rule plus per-component rings; nothing removes focus without a replacement.
- **R-33** no patch scripts in the repo.
- **R-34** both themes carry their own tokens; no mode is a bare invert.
- **R-39** `cursor: pointer` base rule added; native `<button>`/`<a>` used throughout; no clickable `div`.
- **R-10** blur limited to 5 elements (sticky toolbars and the form dock), not cards or nav.
- **R-12** shadows are used for elevation only (dock, tab bar, CTA), not on every card.

## 3. Suggested order

1. Finding 1 (contrast token) — one line, biggest readability win.
2. Finding 2 (em dashes) — mechanical, ~28 strings.
3. Finding 3 (DESIGN.md) — unlocks R-31, R-11, R-05 and stops future drift.
4. Finding 4 (aria-busy) and 6 (motion-safe) — two small edits.
5. Findings 5, 7, 8 — optional polish.

- **R-40 Web Vitals**: not measured, so no score is claimed.
